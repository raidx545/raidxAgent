01 / the privacy boundary

The browser knows
the real world. The model does not.

Raw DOM, screenshots, OCR and the token vault stay inside the extension. RAIDX sends only a meaningful, redacted representation to the planner.

Find what should never leave.

Semantic DOM signals, checksum-backed identifiers, page identity annotations, OCR, and screenshot geometry work together before any egress.

  • email, phone, PAN, Aadhaar, GSTIN
  • names, organisations, addresses
  • face, document, signature regions

Two outputs. One safe context.

Text is renamed into stable join keys. Pixels are irreversibly destroyed on canvas and labelled with the same token so visual context remains useful.

  • Sharma Traders → <ORG_1>
  • email on screen → <EMAIL_1>
  • face region → black box / <PHOTO_1>

02 / proof, not promises

Perception you can audit.
Privacy you can prove.

The security boundary is code, not a system prompt. The extension records what it detected, what it removed, and what was safe to send.

01

Tri-signal perception

DOM extraction, full-page screenshot capture, and local OCR form one page snapshot.

02

Checksum-gated PII

Verhoeff, Luhn, PAN and GSTIN validation reduce false positives with mathematics, not guesses.

03

Text + pixels agree

A token used in the redacted tree is painted into the matching screenshot region.

04

Vault, not storage

Stable mappings exist only in the session-scoped in-memory vault, never in planner context.

05

Safety gate

Credential fields are sealed. Purchases, sends and deletes pause for human confirmation.

06

Re-check the output

RAIDX detects PII again after sanitizing. A residual is a failure, not a warning to ignore.

03 / inspect the evidence

Make the privacy claim testable.

Open the built-in PII inspector to compare the original DOM and screenshot with the tokenized and redacted outputs. The extension also ships browser self-tests for pixel destruction.
